# Repository Guidelines

`CLAUDE.md` is a symlink to `AGENTS.md`; edit `AGENTS.md`.

## Project Structure & Module Organization
- `src/routes/`: SvelteKit routes with `[lang=lang]/` i18n prefix. Both blogs
  share one implementation via `[section=section]` (`tech`, `life`).
  Standalone pages: `about/`, `use/`, and `life/[activity=activity]/`
  (`reading`, `watching`, `listening`).
  Endpoints: `feed/` (runtime RSS), `og/` (prerendered OG images),
  `sitemap.xml/`, `robots.txt/`, `fly/[aircraft=aircraft]/` (prerendered
  flight companions).
- `src/lib/fly/`: the flight companions. `companion.html` is one standalone
  page template shared by every aircraft, served outside the printer shell;
  `<slug>.json` is the checklist payload, generated from the procedure notes
  in github.com/luojiahai/wiki by its `tools/build-companion.mjs` and
  vendored here. Adding an aircraft means a `src/params/aircraft.ts` entry, a
  payload, a `payloads` row in the endpoint, and a summary in both
  dictionaries.
- `src/lib/components/`: Svelte components (printer shell UI, printed
  elements, post list/content).
- `src/lib/dictionaries/`: i18n strings (`en.ts` is the canonical shape,
  `zh.ts` must match). Keep keys in sync.
- `src/lib/content.ts`: typed access to Velite output (posts, categories).
- `content/`: source content. Tech posts in
  `content/tech-posts/YYYY-MM-DD title/`, life posts in
  `content/life-posts/<slug>/`; each post directory holds one `<lang>.md` per
  translation (`en.md`, `zh.md`) plus its images. Translations are optional —
  every file declares its own `lang`, and list pages show only the current
  language. Categories in `content/categories/{tech,life}.yml`.
- `static/`: static assets, copied verbatim. `_headers` (project root) holds
  Cloudflare cache rules. `static/blog/` is generated by Velite (gitignored).
- `assets/icon.svg`: source of truth for the site icons. `pnpm icons`
  (`scripts/generate-icons.mjs`) regenerates `static/{icon.svg,favicon.ico,
  icon.png,icon-192.png,apple-icon.png,mask-icon.svg}` from it; commit the
  regenerated files. `assets/logo.svg` is the original bare-glyph logo,
  kept for reference and not served.
- Root config: `svelte.config.js`, `vite.config.ts`, `velite.config.ts`,
  `wrangler.jsonc`.

## Build, Test, and Development Commands
- `pnpm install`: Install dependencies (pnpm only; no npm/yarn lockfiles).
- `pnpm dev`: Start local dev server (runs Velite in watch mode).
- `pnpm check`: svelte-check type checking. Run before PRs.
- `pnpm build`: Production build; prerenders every page and OG image.
- `pnpm preview`: Build + preview in the Workers runtime (wrangler dev).
- `pnpm deploy`: Build + deploy to Cloudflare Workers.
- `pnpm upload`: Build + upload a Workers preview version (no production
  release).
CI runs check and build on push via `.github/workflows/ci.yml`. Deployment is
handled by Cloudflare Workers Builds (Git integration): its dashboard deploy
commands run `wrangler deploy` on main (production) and
`wrangler versions upload` on other branches (preview only).
`scripts/deploy.mjs` applies the same main-only rule via `WORKERS_CI_BRANCH`
as an in-repo backstop.

## Architecture Notes
- The whole site is prerendered (`prerender = true` in the root layout). The
  worker only handles the `Accept-Language` locale redirect
  (`src/hooks.server.ts`), the extensionless `/feed*` routes, and
  `/api/social`, all cached at the edge with the Cloudflare Cache API.
- `/api/social` serves live GitHub/X profile stats for the social hover
  cards (`src/lib/components/SocialHoverCard.svelte`). It layers caches:
  edge Cache API → `SOCIAL_CACHE` KV last-good snapshot (binding in
  `wrangler.jsonc`; the code tolerates a missing binding in local dev) →
  committed fallback `src/lib/social-fallback.json`.
- OG images are rendered at build time with satori + resvg
  (`src/lib/og/image.ts`); CJK glyph subsets and Twemoji are fetched during
  the build, so builds need network access.
- Icons are inline SVG paths in `src/lib/icons.ts` — no icon packages.
- A new non-localized top-level path must be added to
  `NON_LOCALIZED_PREFIXES` in `src/hooks.server.ts`, or the locale redirect
  swallows it. A new static page also needs an entry in `PAGE_EMOJIS`
  (`src/routes/og/[...path]/+server.ts`) to get an OG image.
- `src/lib/sections.ts` is deliberately separate from `src/lib/content.ts` so
  the `section` param matcher does not pull the Velite output (`#velite`)
  into the client bundle.

## Content Notes
- Post frontmatter (`velite.config.ts`): required `title` (≤99 chars),
  `slug`, `lang`, `date`, `categories`; optional `updated`, `cover`, `video`,
  `description` (≤999), `keywords`, `draft`, `featured`, `wechatLink`.
  Translations are linked by matching `section` + `slug`.
- Every `categories` entry must exist in that section's
  `content/categories/<section>.yml`, or the Velite `prepare` step aborts the
  build. Category `name` is capped at 20 chars, `description` at 100.
- `draft: true` posts render under `pnpm dev` only; they are dropped from the
  production build (`src/lib/content.ts`).

## Coding Style & Naming Conventions
- Language: TypeScript (strict). Framework: SvelteKit 2 + Svelte 5 (runes).
- Indentation: 2 spaces; LF line endings (`.editorconfig`).
- File naming: PascalCase for components (`PrinterShell.svelte`), kebab-case
  or camelCase for modules, camelCase for variables.
- Styling: Tailwind CSS 4 (CSS-first config in `src/app.css`).

## Commit & Pull Request Guidelines
- Commits: clear, imperative messages (e.g., "Update work entries").
- i18n: `zh.ts` must mirror `en.ts` — the shape is type-enforced, so `pnpm
  check` catches drift. Post translations are optional; add `zh.md` only when
  the translation actually exists.
- Content: new tech posts use `content/tech-posts/YYYY-MM-DD title/` with
  `en.md` (plus `zh.md` if translated) and images alongside.
- Checks: there is no test suite — `pnpm check` and `pnpm build` are the gate.
