# Repository Guidelines

`CLAUDE.md` is a symlink to `AGENTS.md`; edit `AGENTS.md`.

## Project Structure & Module Organization
- `src/routes/`: SvelteKit routes with `[lang=lang]/` i18n prefix. The blog
  lives under `posts/`, which covers the list, `[slug]/`, and
  `categories/[categorySlug]/`. Standalone pages: `projects/` (the project
  list from `content/projects/`), `use/` (the
  gear list, from `content/use/`), and `about/` (prose from
  `content/pages/about/`).
  Endpoints: `feed/` (runtime RSS), `api/social/` (runtime profile stats),
  `og/` (prerendered OG images), `sitemap.xml/`, `robots.txt/`.
- `src/lib/components/`: Svelte components: `CockpitShell.svelte` (the
  page chrome), the `Screen*` primitives that pages build from, the post and
  project lists, `PostContent.svelte`, and `SocialHoverCard.svelte`.
- `src/lib/dictionaries/`: i18n strings (`en.ts` is the canonical shape,
  `zh.ts` must match). Keep keys in sync. **Page content belongs in
  `content/`; the dictionaries hold UI strings and typed config only.** Two
  deliberate exceptions stay put: `contacts`, because `kind` binds to
  `SocialCardKind`, which picks what the hover card shows, so moving it to
  YAML would sever that type-checked link to translate one field; and
  `social`, which
  is hover-card chrome, meaningless outside `SocialHoverCard.svelte`.
  Anything with a reader as its audience — prose, a list, a blurb — goes in
  `content/`. Hardware legends (the nav keys, ANN LT, LANG, MASTER WARN)
  stay English uppercase in every language and live in the markup; only
  their accessible names come from the dictionary. Screen content
  translates.
- `src/lib/site-config.ts`: `SITE_URL`, the one origin every absolute URL
  (canonical, OG, feed, sitemap, JSON-LD, share links) is built from.
- `src/lib/content.ts`: typed access to Velite output (posts, pages,
  categories, projects, use). The types are Velite's own, generated from
  the schemas in `velite.config.ts` into `.velite/index.d.ts`, so a schema
  change reaches every consumer with no interface to copy by hand. That only
  holds while the `#velite` alias names the `.velite` directory; pointed at
  `index.js`, TypeScript infers from the JSON and loses the literal types.
  Category post counts are derived here from the published posts, so drafts
  and archived posts never inflate them. Collections with inline-localized
  fields expose a `…Of(lang)` accessor that resolves `{ en, zh }` down to
  plain strings; the raw localized arrays are module-private, so routes and
  components never see that shape.
- `content/`: source content. Posts in `content/posts/YYYY-MM-DD title/`;
  each post directory holds one `<lang>.md` per translation (`en.md`,
  `zh.md`) plus its images. Translations are optional — every file declares
  its own `lang`, and list pages show only the current language. Categories
  in `content/categories/posts.yml`. Standalone page prose in
  `content/pages/<slug>/<lang>.md`, same one-file-per-language shape but
  every language is required, since the route prerenders at a fixed URL in
  each; the route owns the URL, so `slug` is only a lookup key. Pages render
  through the same markdown pipeline as posts. Structured (non-prose) content
  is YAML instead: `content/projects/projects.yml` and
  `content/use/use.yml`. Array order is display order, and only the fields
  that actually vary carry an inline `{ en, zh }`. By convention each of
  these directories holds one array file named after the collection, but the
  patterns are globs (`projects/*.yml`), so splitting a list across files
  would load and merge silently — and ordering would then follow the glob.
- `static/`: static assets, copied verbatim. `_headers` (project root) holds
  Cloudflare cache rules. `static/blog/` is generated by Velite (gitignored);
  `static/static/` is committed by hand and served at `/static/…` (inline
  art), which is why `/static` is a non-localized prefix.
- `assets/icon.svg`: source of truth for the site icons. `pnpm icons`
  (`scripts/generate-icons.mjs`) regenerates `static/{icon.svg,favicon.ico,
  icon.png,icon-192.png,apple-icon.png,mask-icon.svg}` from it; commit the
  regenerated files. `assets/logo.svg` is the original bare-glyph logo,
  kept for reference and not served.
- Root config: `svelte.config.js`, `vite.config.ts`, `velite.config.ts`,
  `wrangler.jsonc`, `tsconfig.json`, `pnpm-workspace.yaml` (the build
  allowlist). pnpm blocks a just-published dependency until it clears the
  release-age window; to take one early, list it under
  `minimumReleaseAgeExclude`, and delete the entry once it has aged out.
  `pnpm install` reports whether the lockfile passes the policy without it.

## Build, Test, and Development Commands
- `pnpm install`: Install dependencies (pnpm only; no npm/yarn lockfiles).
- `pnpm dev`: Start local dev server (runs Velite in watch mode).
- `pnpm check`: svelte-check type checking. Run before PRs.
- `pnpm build`: Production build; prerenders every page and OG image.
- `pnpm preview`: Build + preview in the Workers runtime (wrangler dev).
- `pnpm deploy`: Build + deploy to Cloudflare Workers.
- `pnpm upload`: Build + upload a Workers preview version (no production
  release).
CI runs check and build on push via `.github/workflows/ci.yml`. Deployment is
handled by Cloudflare Workers Builds (Git integration): its dashboard deploy
commands run `wrangler deploy` on main (production) and
`wrangler versions upload` on other branches (preview only).
`scripts/deploy.mjs` applies the same main-only rule via `WORKERS_CI_BRANCH`
as an in-repo backstop.

## Architecture Notes
- The whole site is prerendered (`prerender = true` in the root layout). The
  worker only handles the `Accept-Language` locale redirect
  (`src/hooks.server.ts`), the extensionless `/feed*` routes, and
  `/api/social`, all cached at the edge with the Cloudflare Cache API.
- `/api/social` serves live GitHub/X profile stats for the social hover
  cards (`src/lib/components/SocialHoverCard.svelte`). It layers caches:
  edge Cache API → `SOCIAL_CACHE` KV last-good snapshot (binding in
  `wrangler.jsonc`; the code tolerates a missing binding in local dev) →
  committed fallback `src/lib/social-fallback.json`.
- OG images are rendered at build time with satori + resvg
  (`src/lib/og/image.ts`); CJK glyph subsets and Twemoji are fetched during
  the build, so builds need network access.
- The shell is an A320 cockpit (`CockpitShell.svelte`): a glareshield
  panel (placard, LCD windows, the five ECP nav keys, master lights, the
  ANN LT switch, the LANG knob), one ECAM display holding the page with a
  status strip along its foot, and a pedestal footer. The panel styles live
  in `src/app.css`.
- Light and dark: ANN LT BRT stores `light` and DIM stores `dark` in the
  `color-mode` localStorage key, which the `src/app.html` pre-paint script
  turns into `html.dark` before paint. The lever position is derived, never
  stored, and CSS draws it from `html.dark`. TEST only sets `data-ann-test`
  on the shell root for about a second, and CSS lights every annunciator
  from that one attribute.
- Panel colours are CSS variables on `:root` that `:root.dark` redefines in
  `src/app.css`. Components read them (`var(--panel)`) and never pair a
  `dark:` utility with them, so the DIM decision stays in that one block.
  Screens never change with the mode: the ECAM colours are fixed
  `--color-ecam-*` theme tokens. White is titles, green data values, cyan
  anything clickable, amber drafts, magenta featured posts, and red only the
  404.
- The root `src/routes/+layout.server.ts` loads the post counts per
  language, the project count and the build time (`__BUILD_TIME__`, a Vite
  `define`, so a 404 rendered in the worker still shows the build date)
  for the LCD windows and the status strip. Client components take content
  from load data and never import `$lib/content`, which would ship the
  content JSON to the browser.
- The 404 is an ECAM warning: the shell lights MASTER WARN from
  `page.status` until it is pressed.
- A new non-localized top-level path must be added to
  `NON_LOCALIZED_PREFIXES` in `src/hooks.server.ts`, or the locale redirect
  swallows it. A new static page also needs an entry in `PAGE_EMOJIS`
  (`src/routes/og/[...path]/+server.ts`) to get an OG image.

## Content Notes
- Post frontmatter (`velite.config.ts`): required `title` (≤99 chars),
  `slug`, `lang`, `date`, `categories`; optional `updated`, `cover`, `video`,
  `description` (≤999), `keywords`, `draft`, `archived`, `featured`,
  `wechatLink`.
  Translations are linked by matching `slug`.
- Page frontmatter (`velite.config.ts`): required `slug`, `lang`, `title`
  (≤99 chars); optional `description` (≤999). A page missing a translation
  aborts the build in the Velite `prepare` step.
- Every cap and required field below is enforced: Velite runs with
  `strict: true`, so a schema violation fails `pnpm build` (and CI) instead
  of being logged and shipped. `prepare` gathers every cross-collection
  problem it finds and throws them as one error.
- Project entries (`content/projects/projects.yml`): required `slug`, `name`
  (plain, or `{ en, zh }` for a product named per language),
  `description` (`{ en, zh }`, ≤100 chars each), `link`; optional `image`, a
  path into `static/static/` that nothing validates. The blurb renders
  `line-clamp-1`, so keep it well under the cap.
- Use groups (`content/use/use.yml`): one record per group — `slug`, `label`
  (`{ en, zh }`, ≤20), and `items` of `label` (`{ en, zh }`, ≤30) plus
  `value` (≤60). `value` is a product name, so it is plain, not localized;
  listing something with a language-specific name means widening the schema.
- Every `categories` entry must exist in `content/categories/posts.yml`, or
  the Velite `prepare` step aborts the build. Category `name` is capped at
  20 chars, `description` at 100.
- `prepare` rejects duplicate keys in every collection — posts and pages by
  `lang/slug`, categories, projects and use groups by `slug`, and use
  items by `value`, since they have no slug. These are the keys the list
  pages pass to `{#each}`, and Svelte throws on a repeated key, so a
  duplicate is a broken page rather than a cosmetic slip. Adding a collection
  with a keyed `{#each}` means adding a row to the `keyed` array.
- `draft: true` posts render under `pnpm dev` only; they are dropped from the
  production build (`src/lib/content.ts`). `archived: true` posts stay in
  the repo but never render, in dev or production; the source and its
  images are kept, nothing else.

## Coding Style & Naming Conventions
- Language: TypeScript (strict). Framework: SvelteKit 2 + Svelte 5 (runes).
- Indentation: 2 spaces; LF line endings (`.editorconfig`).
- File naming: PascalCase for components (`CockpitShell.svelte`), kebab-case
  or camelCase for modules, camelCase for variables.
- Styling: Tailwind CSS 4 (CSS-first config in `src/app.css`).
- Fonts: B612 and B612 Mono for chrome, labels and data (`font-ui`,
  `font-mono`), IBM Plex Sans for prose (`font-read`), and Noto Sans SC as
  the CJK fallback in every stack.

## Commit & Pull Request Guidelines
- Commits: clear, imperative messages (e.g., "Update work entries").
- i18n: `zh.ts` must mirror `en.ts` — the shape is type-enforced, so `pnpm
  check` catches drift. Post translations are optional; add `zh.md` only when
  the translation actually exists.
- Content: new posts use `content/posts/YYYY-MM-DD title/` with `en.md`
  (plus `zh.md` if translated) and images alongside.
- Checks: there is no test suite — `pnpm check` and `pnpm build` are the gate.
